# 规则是怎么来的（实测证据）

这份文档记录 house style 每一条规则的**测量依据**，方便你判断该不该改、改了会不会崩。
样本：两套真实图纸 —— 小样本 `家具平面.dxf`（21 个图块 / 127 个实体）与生产库 `家具库.dxf`
（4347 个图块 / 2205 个插入 / 4267 条文字）。

---

## 1. 单位与比例

| 观察 | 数值 |
|---|---|
| 沙发图块外包 | 4000 × 3050 mm |
| 圆餐桌 | ⌀1200 mm |
| `$INSUNITS` | **1（英寸）** —— 与实际不符 |
| INSERT 缩放 | 20/20 全部 `1.0` |
| 唯一带旋转的块 | BF0690，`rotation = 42.4°`（写在 INSERT 上，块内不烘焙） |

→ 结论：**mm、1:1、旋转只在 INSERT**。信几何，不信 header。

---

## 2. 图块内部

| 观察 | 占比 |
|---|---|
| 块内实体在 `layer 0` + `color 0(ByBlock)` + `linetype ByBlock` | 20/21（另一块是后来另一套生成器产的） |
| 包围盒中心 = (0,0) | 20/21 |
| 块内含 TEXT/DIMENSION/HATCH | 0 |
| 单块实体数 | 平均 6.05；**12/21 只有 1 个实体** |

生产库更极端：**256 个边柜里 208 个是单矩形**，108 个书柜里 86 个是单矩形，41 个柜类 25 个单矩形。
→ 结论：**"外形即信息"的家具，一个闭合矩形就是正解**，多画一笔都是噪声。

---

## 3. 椅子共模板（650 口径）

| 观察 | 数值 |
|---|---|
| `CY` 块总数 | 226 |
| 其中 19 实体、536.2×580.6 的块 | **75 个**（同一套描摹几何，含旋转 90° 的 580.6×536.2） |
| 两个真实 SKU 几何比对 | CY0845 vs CY1459：旋转 90° 后 Hausdorff **3.07 mm** |
| 它们对应的产品规格 | 610×630 与 430×490 —— 差了 40% 却共用一张平面 |

→ 结论：**≤650 的餐椅平面分辨不出差异，共模板 + 各自独立块名**是这套图纸的既有做法（不是我们发明的）。

---

## 4. 标签

| 观察 | 命中率 |
|---|---|
| 每件家具 2 条 TEXT（编号 + 品牌） | 20/20 |
| 两条同 x 轴心 | 20/20 |
| 编号在插入点 `+(0,+70)`、品牌在 `+(0,-70)`（字高 100） | 19/20 |
| 标签中心 = INSERT 点 | 17/20 |
| 字高 100 / 颜色 2(编号)、7(品牌) | 19/20 |

偏差的 3 个是人工微调（大沙发下移 883mm 避让轮廓、椅子右移 72mm 避让椅背）。
→ 结论：**规则是默认值，允许小幅人工挪**；脚本按规则重排后不会丢信息。

---

## 5. 尺寸可信度

| 类别 | 与表格/图片标注的偏差 |
|---|---|
| 矩形单体（茶几/餐桌/边柜/书柜） | **完全一致**（1300×700、1800×850、⌀1200、1880×500…） |
| 圆/椭圆 | 完全一致（⌀1000、⌀1200、1830×480） |
| 描摹类椅子 | 比规格**小 8%~12%**（566 vs 610 类） |
| 曲面沙发 | 包围盒 3825×2019 vs 标称长度 3960 —— 弧长 ≠ 包围盒 |

→ 结论：**图块包围盒才是平面占位；表格是营销尺寸**。差异 >20mm 时列进清单，不盲目覆盖。

---

## 6. 数据源的坑（都踩过）

| 坑 | 实测 |
|---|---|
| `bbox.extents(fast=True)` | 同一把椅子给出 **565.7×580.6**，精确值 **536.2×580.6**（差 30mm，因为大半径圆弧被按整圆取极值） |
| 块几何用 OCS 镜像 | 手算 `center + angle` 渲染出镜像的椅子；`path.make_path()` 才对 |
| 共享块名 | 一个 `BF1207` 同时被「待校对」与另一个位置引用，改块定义会同时移动两处 |
| 占位品牌文字 | 真实写法是「名称待核对」，不是「待校对」——按子串判定才稳 |
| ERP 默认方块 | 多个 SKU 都是 `1000×1000`；实际 1700×800、2820×1050… 只能从 SKU 图读 |
| 备注层 | 每条占位块下有「待校对 1480 × 1040 mm」+ 一个整层标题，校对完要整层清 |

## 8. OCR 读尺寸的实测（Windows.Media.Ocr）

样本：表格里查不到、只能看图的 7 个 SKU。

| SKU | 图上的字 | OCR 结果 | 判定 | 正确？ |
|---|---|---|---|---|
| TZ2614 | 1.7m / 0.8m / 0.76m / 0.56m / 0.65m | 1700 / 800 / 760 / 560 / 650 | default-square → **1700×800** | ✅（书桌 1.7×0.8） |
| TZ3818 | 总长340cm / 总深174cm / 靠高36 / 坐高40 | 3400 / 1740 / 360(高) / 400(高) | default-square → **3400×1740** | ✅（RIVIER 组合B） |
| TZ4068 | 282cm / 105cm / 78cm | 2820 / 1050 / 780 | default-square → **2820×1050** | ✅（雷诺沙发） |
| TZ3661 | 0.95m / 0.8m / 0.65m …（L/M/S 三款） | 950 / 800 / 650 … | 文字含「圆形茶几」→ **⌀950** | ✅（取 L 款） |
| CZ0825 | 1.8m / 0.83m / 0.77m / 0.75m | 1800 / 830 / 770 / 750 | confirm 1800×800 | ✅（差 30mm，不折腾） |
| DG0606 | 1.57m / 0.45m / 0.81m | 1570 / 450 / 810 | confirm 1570×450 | ✅ |
| TZ4709 | 72cm / 87cm / 95cm（椅）+ 58/56/42（脚蹬） | 950 / 870 / 720 / 580… | default-square → 950×870 ⚠ | ⚠ 95cm 是总高，应取 870×720 |

**结论**：7 个里 6 个直接可用，1 个（套装/高脚椅）需要人看一眼——所以 `ocr-default-square` 在两值接近时会打 ⚠ 并进复核清单。

三个必须做的归一化（否则一个都读不出）：

1. 中文 OCR 在字符间插空格：`1 ． 7 m` → `1.7m`，`1 7 4 c m` → `174cm`
2. 中点/逗号当小数点：`1 · 8 m` → `1.8m`，`0 ， 76m` → `0.76m`
3. 双引擎：英文引擎数字准，中文引擎才能给出「圆形茶几」「靠高」这类关键词

**容差经验**：`near()` 用 `max(15% , 15mm)`。太紧会把"表格 830 / 图 800"判成冲突，太松会把 1000 默认方块和 950 判成一致（这也是要先排除方形占位块的原因）。
